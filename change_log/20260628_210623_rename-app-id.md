# Change log — rename namespace + applicationId to `in.sreerajp.contact_sphere`

Implements [plans/20260628_210623_rename-app-id.md](../plans/20260628_210623_rename-app-id.md).

## Changes

### `android/app/build.gradle.kts`
- `namespace` → `in.sreerajp.contact_sphere` (was `com.example.smart_contacts_dialer`).
- `applicationId` → `in.sreerajp.contact_sphere`.
- Removed the now-obsolete `// TODO: Specify your own unique Application ID` comment.

### MainActivity moved to match the new package
- New file `android/app/src/main/kotlin/in/sreerajp/contact_sphere/MainActivity.kt`.
- Package declaration is `` package `in`.sreerajp.contact_sphere `` — the first
  segment is backtick-escaped because `in` is a hard keyword in Kotlin. The
  fully-qualified class name remains `in.sreerajp.contact_sphere.MainActivity`, so
  the manifest's `.MainActivity` still resolves.
- Deleted the old package tree `android/app/src/main/kotlin/com/` entirely.

`AndroidManifest.xml` was not touched — it references `.MainActivity` and
`${applicationName}`, both relative to the namespace.

## Verification
- `flutter clean` then `flutter build apk --debug` → **`√ Built app-debug.apk`**.
  (The build log contains a non-fatal Kotlin incremental-cache warning — the pub
  cache on `H:` vs. the project on `L:` can't be relativized across drive roots —
  and a `speech_to_text` deprecation warning; neither affects the build.)
- `build/app/outputs/apk/debug/output-metadata.json` confirms
  `"applicationId": "in.sreerajp.contact_sphere"`.

## Notes
- Because `applicationId` changed, Android treats this as a new app: an existing
  install of the old id installs side-by-side rather than upgrading, and its local
  SQLite data does not carry over. Expected for a pre-release rename.
- Release signing unchanged (still debug keys per the existing TODO in build.gradle.kts).
