## Plan Reference
Implements the plan [20260719_150016_contact_intents.md](file:///L:/Android/SreerajPContactSphere/plans/20260719_150016_contact_intents.md).

## What Changed

### Android Manifest
* File: `android/app/src/main/AndroidManifest.xml`
* Registered `MainActivity` for standard contact intent actions (`VIEW`, `EDIT`, `INSERT`, `INSERT_OR_EDIT`, `PICK`, `GET_CONTENT`) and their directory / item MIME types (`vnd.android.cursor.dir/contact`, `vnd.android.cursor.dir/person`, `vnd.android.cursor.dir/phone_v2`, `vnd.android.cursor.dir/email_v2`, etc.).

### Android Native Handling
* File: `android/app/src/main/kotlin/in/sreerajp/contact_sphere/MainActivity.kt`
* Setup the MethodChannel `contact_sphere/contact_intents` to retrieve parked intents and submit picker results.
* Added native query helpers (`resolvePhoneDataUri`, `resolveEmailDataUri`) to lookup the exact ContactsContract database data row ID for phone number and email picks, ensuring third-party apps receive fully resolved system URIs.

### Flutter Routing & Service
* File: [NEW] `lib/services/contact_intent_service.dart`
* Created a lightweight wrapper to check for pending contact intents and call result submission.
* File: `lib/main.dart`
* Integrated intent checking during cold start (`_bootstrap`) and warm delivery (`initState`).
* Implemented routing logic to open the detail view (`VIEW`), pre-filled form (`INSERT`/`EDIT`), or picker list (`PICK`).

### Flutter Contact Picker UI
* File: `lib/screens/contact_list_screen.dart`
* Extended `ContactListScreen` to accept `pickerMode` and `onContactSelected` arguments.
* In picker mode, hidden the main header/FABs and routed card taps to select contacts and return results immediately instead of opening detail sheets.
