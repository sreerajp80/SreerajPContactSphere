# Change log — Release build signing

Implements plan [plans/20260711_010920_release-signing.md](../plans/20260711_010920_release-signing.md).

## What changed

The release build no longer signs with the shared public **debug** key. It now signs with a
real production keystore, loaded from a git-ignored secrets file, with a safe fallback so
developer/CI builds without the keystore still work.

## Files changed

**Changed**
- `android/app/build.gradle.kts`
  - Added `import java.util.Properties` and a loader that reads `android/key.properties`
    (via `rootProject.file("key.properties")`) when it exists.
  - Added a `signingConfigs { create("release") { … } }` block that reads `keyAlias`,
    `keyPassword`, `storeFile`, and `storePassword` from those properties. `storeFile` is
    resolved relative to the `android/app` module.
  - `buildTypes.release.signingConfig` now uses the `release` config when `key.properties`
    exists, otherwise falls back to the `debug` config (so `flutter run --release` works
    without the production keystore). Removed the stale TODO.
- `.gitignore` (repo root) — added `*.jks`, `*.keystore`, and `key.properties` so the
  root-level `keystore.jks` and any `key.properties` can never be committed. (The existing
  `android/.gitignore` only covered these inside `android/`, which is why the root keystore
  was previously unprotected.)

**Added (committed)**
- `android/key.properties.example` — template with empty placeholders and a documented
  `storeFile=../../keystore.jks` default. No secrets; safe to commit.

**Not committed / handled by me**
- The keystore (`keystore.jks`) and the real `android/key.properties` — these hold secrets
  and are git-ignored. No keystore password, key password, or alias was requested or stored.

## Verification

- `git check-ignore keystore.jks` → ignored; `android/key.properties` → ignored;
  `android/key.properties.example` → not ignored (committable).
- `git status` shows no keystore or `key.properties` — only the `.example` template.
- `./gradlew :app:help` configures successfully (exit 0), confirming the Kotlin DSL parses
  and the signing config resolves. A full `flutter build apk --release` was not run here
  because it needs the real `android/key.properties`, which only the user can create.

## Required user action before a signed release

1. `cp android/key.properties.example android/key.properties`
2. Fill in `storePassword`, `keyPassword`, and `keyAlias` (and adjust `storeFile` if the
   keystore is moved).
3. Build: `flutter build apk --release` (or `flutter build appbundle`).

## Notes

- The keystore currently lives at the repo root. It is now git-ignored, but keeping it
  outside the repository entirely is even safer; `storeFile` can be an absolute path.
- If publishing to Google Play later, enrol in Play App Signing on the first upload so the
  upload key stays rotatable.
