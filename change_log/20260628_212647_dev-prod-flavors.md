# Change log: Add dev/prod product flavors to Android build

Implements plan: `plans/20260628_212145_dev-prod-flavors.md`

## What changed

### `android/app/build.gradle.kts`
Added an `env` flavor dimension with two product flavors inside the `android { }` block:

- `dev` — `applicationIdSuffix = ".dev"` (applicationId `in.sreerajp.contact_sphere.dev`),
  `versionNameSuffix = "-dev"`, `resValue("string", "app_name", "ContactSphere Dev")`.
- `prod` — no suffix (applicationId stays `in.sreerajp.contact_sphere`),
  `resValue("string", "app_name", "ContactSphere")`.

### `android/app/src/main/AndroidManifest.xml`
Changed the application label from the hardcoded `android:label="smart_contacts_dialer"`
to `android:label="@string/app_name"`, so the launcher label is supplied by the per-flavor
generated `app_name` resource.

## Result
- `flutter run --flavor dev` now builds `assembleDevDebug` (id `…contact_sphere.dev`,
  label "ContactSphere Dev").
- `flutter run --flavor prod` builds with id `…contact_sphere`, label "ContactSphere".
- Verified no pre-existing `app_name` string resource conflicts with the generated `resValue`.

## Note
Because flavors now exist, `flutter run` / `flutter build` must always pass
`--flavor dev` or `--flavor prod`; running with no flavor will fail.
