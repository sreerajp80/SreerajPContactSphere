# Change log — App-lock setting

Implements plan `plans/20260710_224213_app-lock-setting.md`.

## What changed

Added a **whole-app biometric lock**. When enabled (Settings → App lock), opening
the app — on cold start and when returning from the background — requires a device
unlock (fingerprint / face / PIN) before the contents are shown. Reuses the
existing `AuthService`; no new native code or dependency.

## How

- `lib/state/app_settings.dart`
  - New persisted pref `app_lock_enabled` (default off) with getter,
    `setAppLockEnabled()`, `load()` wiring, and a static `readAppLockEnabled()`
    for the launch gate (which runs before `load()` completes).
- `lib/screens/app_lock_screen.dart` (new)
  - Full-screen lock: prompts via `AuthService.authenticate` on first show, offers
    an **Unlock** button to retry, and blocks the back gesture/button
    (`PopScope(canPop: false)`); pops (returns `true`) only on success.
- `lib/main.dart`
  - `_SmartContactsAppState` now `WidgetsBindingObserver`; registers/removes the
    observer.
  - `_maybeLock()` shows the lock when it is due and enabled, awaiting the unlock
    so the launch path stays behind it. It no-ops when the device can't
    authenticate (so the user is never trapped) and never shows over a live call
    (`_inCallRoute.isCurrent`). Guarded against overlapping lifecycle events.
  - Locks on cold start (from `_bootstrap`, before the permission prompts) and
    re-arms on `paused` so the next `resumed` re-locks.
- `lib/screens/settings_screen.dart`
  - New inline **App lock** switch card near the top. Disabled with an
    explanatory subtitle when the device has no screen lock configured.

## Verification

- `flutter analyze` — no issues.
- `flutter test test/widget_test.dart` — passed (home shell still renders;
  lock is off by default).
