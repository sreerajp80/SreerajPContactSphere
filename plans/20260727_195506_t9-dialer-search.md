# T9 Smart Dialing Search Implementation Plan

## Issue Description
Currently, when a user types digits on the dialpad (e.g. `5646` for `J-O-H-N`), the dialer (`DialerScreen` -> `ContactRepository.findByPhoneFragment`) only filters contacts by phone number digits (`LIKE '%5646%'`). It does not perform T9 Smart Dialing matching against contact names.

## Proposed Fix
Implement dual T9 Smart Dialing + Phone Number matching in `ContactRepository.findByPhoneFragment` with smart relevance ranking:

1. **`lib/utils/t9_utils.dart` [NEW]**:
   - Create utility class `T9Utils` for letter-to-digit T9 mapping (`2=abc`, `3=def`, `4=ghi`, `5=jkl`, `6=mno`, `7=pqrs`, `8=tuv`, `9=wxyz`).
   - Implement `isT9Match(String name, String typedDigits)`:
     - Handles Latin script as well as Malayalam script via `MalayalamTransliterator`.
     - Matches if `typedDigits` is a T9 prefix of any word in the contact name (e.g., `5646` matches "John", `363` matches "Doe" in "John Doe").
   - Implement `scoreMatch(String name, String number, String typedDigits)` to rank matches:
     - Priority 1: Primary name word-prefix T9 match.
     - Priority 2: Phone number prefix match.
     - Priority 3: Middle substring match (name or number).

2. **`lib/repositories/contact_repository.dart` [MODIFY]**:
   - Update `findByPhoneFragment(String fragment, {int limit = 8})`:
     - Fetch candidate contacts from SQLite.
     - Evaluate both phone digit substring matching and T9 name matching via `T9Utils`.
     - Deduplicate phone matches by `contactId` + `number`.
     - Sort results by relevance score descending and first name ascending, returning top `limit` matches.

3. **`test/t9_utils_test.dart` [NEW]**:
   - Add comprehensive unit tests verifying:
     - Digit-to-letter T9 conversion.
     - Word-prefix and multi-word T9 name matching.
     - Malayalam transliterated name T9 matching.
     - Combined ranking order (name prefix > phone prefix > substring).
