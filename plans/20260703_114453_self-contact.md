# Plan: "Self" contact (the phone owner's own details), pinned first in the list

**Status:** completed

## What the user wants

A provision to create a **Self contact** — the details of the person using the phone.
It must be shown **first in the contact list, irrespective of the sort order**.

## The issue / gap

There is no notion of an "owner"/"me" contact today. Every contact is an equal row in
`contacts`, and the list is ordered strictly by `first_name` (see
`ContactRepository.getContactSummaries` and `ContactSyncService.mergedContacts`). So the
user's own record — if they even add one — sorts alphabetically like anyone else and there
is no way to mark it as "this is me".

## Design decisions (please confirm)

1. **Represent Self as a flag on `contacts`: a new `is_self INTEGER DEFAULT 0` column.**
   The Self contact is an ordinary contact aggregate (name, phones, emails, photo, etc.)
   plus this one flag — so it reuses the whole existing add/edit/detail machinery.
2. **Singleton.** At most one contact may have `is_self = 1`. Saving a contact as Self
   clears the flag on any previous Self (enforced inside the repository transaction).
3. **Pinned first.** The Self contact renders at the very top of the contact list, above
   the alphabetical list, regardless of name — both in the normal list and (only if it
   matches) during search.
4. **App-only, like a secret contact.** Self is **not** pushed to the device address book
   (avoids creating a duplicate "me" in the shared address book / the OS profile is a
   separate concept). This mirrors the existing secret-contact rule in
   `ContactSyncService.saveContact`. *(If you'd rather have Self sync to the device like a
   normal contact, say so and I'll drop this rule.)*
5. **Health hero.** The "Relationship health" average **excludes** Self (its score is
   meaningless as your own record). The contacts **count** still includes Self (keeping the
   count consistent with the paged list query, so paging stays correct); the "N contacts"
   number will therefore include your own record. *(Alternative: exclude Self from the count
   too and render it as a separate pinned header — more UI plumbing. I chose the simpler,
   robust option; tell me if you prefer the exact count.)*
6. **Entry points:** (a) a **"This is me" toggle** in the Add/Edit screen (styled like the
   existing "Secret contact" toggle), and (b) a **"My Profile"** item in the contact-list
   overflow menu that opens the Self contact if it exists, or opens Add/Edit pre-set as Self
   if it doesn't (discoverability).
7. **Safety:** exclude Self from duplicate detection so you can never accidentally merge
   yourself into another contact.

## Files to change

- **`lib/database/database_helper.dart`**
  - Bump DB `version` 10 → **11**.
  - Add `is_self INTEGER DEFAULT 0` to the `contacts` table in `_onCreate`.
  - Add a `v10 -> v11` branch in `_onUpgrade` (`ALTER TABLE contacts ADD COLUMN is_self ...`).
  - Add `idx_contacts_is_self` to `_createIndexes` and the migration.

- **`lib/models/contact.dart`**
  - Add `bool isSelf` field (default `false`), constructor param, `toMap` (`'is_self'`),
    and `fromMap` (`map['is_self'] == 1`).

- **`lib/repositories/contact_repository.dart`**
  - Add `c.is_self` to the shared `_summarySelect` projection.
  - `getContactSummaries`: filter `c.is_self = 0` (Self is fetched/pinned separately);
    keep `ORDER BY c.first_name ASC`.
  - `countContacts`: exclude Self (`is_self = 0`) so it stays consistent with the paged
    list query. *(Note: this changes decision 5 — see below; I'll actually keep count and
    the list query consistent. Both exclude Self.)*
  - `averageRelationshipScore`: exclude Self (`is_self = 0`).
  - `searchContactSummaries`: **include** Self and order `c.is_self DESC, c.first_name ASC`
    so a matching Self sorts first.
  - `getAllContacts`: `ORDER BY is_self DESC, first_name ASC` (for the first-run merged read).
  - New `getSelfSummary()` — slim `_summarySelect WHERE c.is_self = 1 LIMIT 1` → `Contact?`.
  - New `getSelfContact()` — fully hydrated Self (`WHERE is_self = 1`) → `Contact?`.
  - Enforce the singleton in `insertContact`/`updateContact`: when `contact.isSelf`, run
    `UPDATE contacts SET is_self = 0 WHERE is_self = 1 AND id != ?` inside the transaction.
  - `findDuplicates` / `findDuplicateGroups`: add `c.is_self = 0 AND (...)` to exclude Self.

  > Correction to decision 5: to keep offset paging correct, **`getContactSummaries` and
  > `countContacts` must agree**. Both will **exclude** Self. The Self contact is loaded
  > separately (`getSelfSummary`) and prepended by the list screen. The "N contacts" count
  > then excludes Self (honest count), and the average also excludes Self. This is the clean
  > and consistent choice; it just needs the list screen to render Self as a pinned item
  > (below).

- **`lib/services/contact_sync_service.dart`**
  - New `selfSummary({includeSecret})` → `_repo.getSelfSummary()`; `selfContact()` →
    `_repo.getSelfContact()`.
  - `saveContact`: treat `c.isSelf` as app-only (same branch as `c.isSecret`): clear
    `deviceId`, and if it was previously linked, delete the device contact. (Combine the
    condition: app-only when `c.isSecret || c.isSelf`.)
  - `mergedContacts`: change the sort comparator to pin Self first, then by first name.

- **`lib/screens/add_edit_contact_screen.dart`**
  - Add `final bool initialIsSelf;` constructor param (default `false`).
  - Add `_isSelf` state, initialized from `widget.contact?.isSelf ?? widget.initialIsSelf`.
  - On `_save`, set `..isSelf = _isSelf`.
  - Add a `_selfSection()` toggle (a copy of `_secretSection`'s layout: title
    "This is me", subtitle "Your own details — pinned to the top") placed just above the
    secret section in the build list.

- **`lib/screens/contact_list_screen.dart`**
  - Add `Contact? _self;` state; load it in `_reload` via `_sync.selfSummary(...)`.
  - Render the Self card **first** when `_searchQuery.isEmpty && _self != null` (during
    search, Self appears only if it matches, via `searchSummaries` which includes it).
    Adjust the `ListView.builder` `itemCount`/index math for the optional leading Self card
    alongside the existing trailing paging spinner.
  - Give the Self card a small **"YOU"** pill (reuse the group-chip style) via a flag on
    `_buildContactCard`.
  - Add a **"My Profile"** overflow menu item + `_openSelf()` handler: open the Self
    contact's detail if it exists, else push `AddEditContactScreen(initialIsSelf: true)`;
    `_reload()` on return.

## Out of scope (noted, not changing)

- Export/Import CSV does not carry the `is_self` flag (a re-imported Self comes back as a
  normal contact). 
- The device OS "Me/profile" contact is not linked (Self is app-managed).
- The dialer's Favorites/Top lists need no change — Self naturally won't appear (no
  favorite flag, no relationship score, no call logs).
- No new automated tests planned unless you want them; `Contact`'s new field is optional so
  existing tests/`widget_test.dart` keep compiling.
