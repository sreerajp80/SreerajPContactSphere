# Plan - Support Android Contact Intents

**Status:** completed

## Issue
Currently, when other apps open contact lists, edit contacts, or view contacts, they do not use SreerajPContactSphere because SreerajPContactSphere is missing key intent-filters in its manifest and is missing native/Flutter logic to process view, edit, insert, and pick intents.

## Proposed Changes

### Android Manifest
* File: `android/app/src/main/AndroidManifest.xml`
* Add intent-filters inside the `.MainActivity` activity tag for:
  - `android.intent.action.VIEW` for `vnd.android.cursor.dir/contact` and `vnd.android.cursor.dir/person`.
  - `android.intent.action.INSERT_OR_EDIT` for contact items.
  - `android.intent.action.PICK` and `android.intent.action.GET_CONTENT` with directories and item MIME types.

### MainActivity Native Handling
* File: `android/app/src/main/kotlin/in/sreerajp/contact_sphere/MainActivity.kt`
* Define method channel `contact_sphere/contact_intents`.
* Parse incoming contact intents on creation (`onCreate`) and new intent (`onNewIntent`).
* Store parsed intent metadata in a pending map.
* Handle platform method calls:
  - `getPendingContactIntent` to fetch/clear the map.
  - `submitContactPickerResult` to set the result URI and finish the activity.

### Flutter Intent Service
* File: [NEW] `lib/services/contact_intent_service.dart`
* Wraps the `contact_sphere/contact_intents` channel.
* Exposes methods/stream to query and reply to native contact intents.

### Flutter Main Routing
* File: `lib/main.dart`
* Listen for contact intents in `initState` and `_bootstrap`.
* Route actions accordingly:
  - **VIEW / EDIT**: Map system device contact ID to internal SQLite ID and open `ContactDetailScreen` or `AddEditContactScreen`.
  - **INSERT**: Create pre-filled Contact and open `AddEditContactScreen`.
  - **PICK**: Open `ContactListScreen` in picker mode.

### Flutter Contact Picker UI
* File: `lib/screens/contact_list_screen.dart`
* Add optional constructor parameters `pickerMode` and `onContactSelected`.
* In picker mode, tapping a contact returns its data instead of pushing the detail view.

## Verification
* Run `flutter analyze` to ensure code compiles and passes lints.
* Test triggering picking and viewing from third-party apps on a device/emulator.
