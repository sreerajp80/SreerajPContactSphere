# Plan: Split CLAUDE.md to keep context small + add workflow rules

**Status:** completed

## Issue

`CLAUDE.md` is loaded into Claude's context on every session. The current file is large
(commands + full architecture + DB schema + known-gaps + dependency catalog), which consumes
context unnecessarily. The user wants:

1. CLAUDE.md split so the always-loaded portion stays small, with detail moved into
   separate docs that Claude reads on demand.
2. The global workflow rules (mandatory `plans/` approval gate + `change_log/`) documented in
   the project's CLAUDE.md so they are visible per-project.

## Files to be changed / created

- **`CLAUDE.md`** (edit/rewrite) — slim it down to: project one-liner, essential commands,
  a short architecture summary, the workflow rules, and links pointing to the detail docs below.
- **`docs/architecture.md`** (new) — the layered architecture detail + database schema section
  (moved out of CLAUDE.md).
- **`docs/known-gaps.md`** (new) — the "early scaffold / missing pieces" section (moved out).
- **`docs/dependencies.md`** (new) — the heavy-dependencies / intended-features catalog (moved out).

No code files are touched.

## Plan for the fix

1. Create the `docs/` folder with the three detail files, moving the corresponding sections
   verbatim (lightly edited for standalone readability) out of the current CLAUDE.md.
2. Rewrite CLAUDE.md to a lean version:
   - Project summary (2–3 lines).
   - Commands block (kept — small and high-value).
   - A short "Architecture at a glance" paragraph + a "Detailed docs" list linking to
     `docs/architecture.md`, `docs/known-gaps.md`, `docs/dependencies.md` with a one-line hook
     each so Claude knows when to open them.
   - A "Project workflow rules (mandatory)" section restating the global plan→approval→change_log
     rules so they're explicit for this repo.
3. Result: CLAUDE.md stays small; detail is one Read away when actually needed.

## After implementation

Write a change log to `change_log/` per the workflow rules.
