# Add dev/prod product flavors to Android build

**Status:** completed

## Issue

Running `flutter run -d emulator-5554 --flavor dev` fails:

```
Task 'assembleDevDebug' not found in root project 'android'...
The ...\android\app\build.gradle.kts file does not define any custom product flavors.
You cannot use the --flavor option.
```

`android/app/build.gradle.kts` defines no `productFlavors`, so Flutter's `--flavor dev`
has no matching Gradle task. We want a `dev` and a `prod` flavor so dev/prod builds can
be installed side by side and told apart.

## Files to change

1. `android/app/build.gradle.kts` — add a flavor dimension + `dev`/`prod` flavors.
2. `android/app/src/main/AndroidManifest.xml` — make the app label flavor-driven.

## Plan for the fix

### 1. `android/app/build.gradle.kts`

Inside the `android { }` block (after `buildTypes { }`), add:

```kotlin
flavorDimensions += "env"

productFlavors {
    create("dev") {
        dimension = "env"
        applicationIdSuffix = ".dev"      // -> in.sreerajp.contact_sphere.dev
        versionNameSuffix = "-dev"
        resValue("string", "app_name", "ContactSphere Dev")
    }
    create("prod") {
        dimension = "env"
        // keeps applicationId = in.sreerajp.contact_sphere
        resValue("string", "app_name", "ContactSphere")
    }
}
```

Rationale:
- `applicationIdSuffix = ".dev"` lets dev + prod coexist on one device.
- `resValue("string", "app_name", ...)` generates a per-flavor `app_name` string so the
  two builds show different launcher labels.
- `prod` carries no suffix, so the release/prod applicationId stays
  `in.sreerajp.contact_sphere` (unchanged from today).

### 2. `android/app/src/main/AndroidManifest.xml`

Change the hardcoded label so it resolves from the generated per-flavor resource:

```xml
android:label="@string/app_name"
```

(currently `android:label="smart_contacts_dialer"`).

## Verification

- `flutter run -d emulator-5554 --flavor dev` builds `assembleDevDebug` and launches with
  applicationId `in.sreerajp.contact_sphere.dev`, label "ContactSphere Dev".
- `flutter run -d emulator-5554 --flavor prod` builds with applicationId
  `in.sreerajp.contact_sphere`, label "ContactSphere".
- `flutter build apk --flavor prod` produces a prod APK.

## Notes / follow-ups (not in this change)

- `flutter run` with **no** `--flavor` will stop working once flavors exist — Flutter
  requires a flavor to be chosen once any are defined. All run/build commands must pass
  `--flavor dev|prod` afterward.
- Optional later: per-flavor Dart entrypoints (`lib/main_dev.dart`) and `--dart-define`
  for environment config. Out of scope here.
