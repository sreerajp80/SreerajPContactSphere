# Group overflow-menu items: "Import / Export" and "Bluetooth transfer"

**Status:** completed

## Issue

The overflow (three-dot) menu on the contacts list has 10 items. Four of them are
import/export actions (CSV and vCard) and two are Bluetooth actions (send all,
receive). The long flat list is hard to scan.

## Fix (Option A — chooser bottom sheets)

Replace the six related menu items with two grouped items. Each grouped item opens
a small bottom sheet where the user picks the exact action. The existing action
code does not change; only how the user reaches it changes.

New menu layout:

1. My Profile
2. Import / Export        → opens sheet: Import CSV, Export CSV, Import vCard (.vcf), Export vCard (.vcf)
3. Bluetooth transfer     → opens sheet: Send all via Bluetooth, Receive via Bluetooth
4. Scan QR code
5. Find Duplicates
6. ─────────
7. Settings

## Files to change

- `lib/screens/contact_list_screen.dart` (only file):
  - In `_buildHeader` (~line 655): replace the four CSV/vCard items with one
    `PopupMenuItem(value: 'import_export', ...)` and the two Bluetooth items with
    one `PopupMenuItem(value: 'bluetooth', ...)`.
  - In `_handleMenu` (~line 464): add cases `'import_export'` and `'bluetooth'`.
    Each shows a `showModalBottomSheet<String>` chooser and, based on the picked
    value, falls through to the existing handling by calling
    `_handleMenu('<original value>')` again (e.g. `'import'`, `'export_vcf'`,
    `'send_all_ble'`, `'receive_ble'`). The original cases stay unchanged.
  - Sheet style copies the app's existing pattern (e.g. the call-history action
    sheet): `showDragHandle: true`, a short bold title, `ListTile`s with an icon
    and a clear label each, popping a string value. Labels stay explicit
    ("Import CSV", "Export CSV", ...) so import and export can never be mixed up.

## Notes

- No new files, no new dependencies, no behavior change to the actions themselves.
- Follows the app's own design system (bottom sheets already used across screens),
  per the project's UI rule.
- Verify with `flutter analyze` and a quick manual run of each menu path.
