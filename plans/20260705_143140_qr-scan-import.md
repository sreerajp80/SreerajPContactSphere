# QR scanning — import a contact by scanning a QR code

**Status:** completed

## Issue

Sharing a contact as a QR code shipped on 2026-07-03 (`lib/services/qr_share_service.dart`,
`lib/widgets/qr_share_dialog.dart` — the payload is a vCard 3.0 built by
`VCardService.qrPayload`), but the app has no way to **read** one. The discontinued
`qr_code_scanner` package was dropped from `pubspec.yaml` and nothing replaced it.
[docs/known-gaps.md](../docs/known-gaps.md) explicitly recommends `mobile_scanner` when this
gets built.

## Plan

Add a camera QR-scan screen that reads a vCard QR code (ours or any standard contacts-app
QR) and routes the result through the exact same review/import flow the `.vcf`-intent path
in `main.dart` already uses.

### 1. Dependency

- `pubspec.yaml`: add `mobile_scanner: ^7.0.1` (ML Kit-based, maintained successor to
  `qr_code_scanner`). Run `flutter pub get`.

### 2. Android manifest

- `android/app/src/main/AndroidManifest.xml`: declare
  `<uses-permission android:name="android.permission.CAMERA"/>` with a short comment
  (mobile_scanner merges it from its own manifest, but the project convention is that every
  used permission is listed and commented here). No runtime-permission code is needed —
  the `MobileScanner` widget requests camera permission itself and reports denial through
  its `errorBuilder`.

### 3. New screen — `lib/screens/qr_scan_screen.dart`

`QrScanScreen`, pushed as a normal route, pops with `true` when at least one contact was
saved (so the caller can reload):

- Full-screen `MobileScanner` limited to QR symbology
  (`MobileScannerController(formats: [BarcodeFormat.qrCode])`), with a torch toggle in the
  app bar and a small hint text ("Point the camera at a contact QR code"). Styling follows
  the app's own design system (`AppColors` / theme accent), not a Google Lens clone.
- `errorBuilder` shows an in-place message with an "Open settings" hint when camera
  permission is denied; everything stays inside the screen (no crash, no dialog storm).
- On detect (debounced — first hit wins, scanner stopped while handling):
  - Payload not starting with `BEGIN:VCARD` (trimmed, case-insensitive) → snackbar
    "Not a contact QR code", resume scanning.
  - Parse with `VCardService().fromVCard(...)` (same parser as the `.vcf` import paths).
  - **0 contacts** → snackbar "Could not read a contact from this code", resume scanning.
  - **1 contact** → push `AddEditContactScreen(contact: parsed.first)` for review; saving
    runs the normal two-way sync (identical to the single-contact vCard-intent flow in
    `main.dart`). If saved, pop the scan screen with `true`; otherwise resume scanning.
  - **>1 contacts** → confirm dialog, then bulk-save through
    `ContactSyncService().saveContact(...)` (identical to the multi-contact vCard-intent
    flow in `main.dart`), snackbar with the count, pop with `true`.
- Proper lifecycle handling per mobile_scanner docs: controller created in `initState`,
  disposed in `dispose`, start/stop on `AppLifecycleState` changes via
  `WidgetsBindingObserver`.

### 4. Entry point — `lib/screens/contact_list_screen.dart`

- Add a **"Scan QR code"** item to the existing overflow `PopupMenuButton` (grouped with
  the Import CSV / Import vCard entries — scanning is an import path) with a new
  `_handleMenu` case that pushes `QrScanScreen` and calls `_reload()` when it returns
  `true`.

### 5. Docs

- `docs/known-gaps.md`: move the QR bullet out of "Still not integrated" — share **and**
  scan are now wired; note `mobile_scanner` replaced the discontinued `qr_code_scanner`.
- `docs/dependencies.md`: update the QR line to `qr_flutter` (render) + `mobile_scanner`
  (scan).

## Verification

- `flutter analyze` — no **new** issues (the pre-existing known-gaps errors stay as-is).
- `flutter test` — existing suite still passes.
- Manual (device): scan the app's own QR share dialog from a second device / printed code →
  Add/Edit opens pre-filled → save lands in app DB + device book; non-contact QR (URL) →
  "Not a contact QR code"; camera permission denied → in-screen message, no crash.

## Out of scope

- MECARD / ZXing contact format payloads (vCard only — that's what our share emits and
  what stock contacts apps emit).
- Scanning a QR from an image in the gallery (mobile_scanner supports `analyzeImage`;
  can be a follow-up).
- BLE/speech/other known-gaps items.
