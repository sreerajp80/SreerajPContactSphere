# Tags & Groups UX improvements

**Status:** completed

## What the user asked for

1. **Tags — case-insensitive match, then select-or-create.**
   In the contact editor Tags field, when the user types a tag it should match
   existing tags without caring about upper/lower case. The user then either
   picks a listed (existing) tag or creates a new one.

2. **Groups — same select-or-create approach in the contact editor.**
   Right now every group is shown as a chip. With more than ~10 groups this is
   messy. Groups should work like tags: type to search (case-insensitive), pick
   a listed group or create a new one. Already-selected groups stay visible as
   removable chips.

3. **Groups page — add contacts to a group from there.**
   From the Groups screen the user should be able to open a group and add
   contacts to it (multi-select), not only from the contact editor.

## Files to change

1. `lib/screens/add_edit_contact_screen.dart`
   - Feature 1 (tags): fix case-insensitive add + let an exact case-insensitive
     match of an existing tag still show as a selectable suggestion.
   - Feature 2 (groups): replace the "list every group as a chip" UI with a
     tag-style search box + suggestions, keeping selected groups as removable
     chips.

2. `lib/screens/groups_screen.dart`
   - Feature 3: add an "Add contacts…" action per group that opens a
     multi-select contact picker and adds the chosen contacts to the group.

3. `lib/repositories/group_repository.dart`
   - Feature 3: add a helper `contactIdsInGroup(int groupId)` so the picker can
     pre-check contacts already in the group. (`addContactToGroup` already
     exists and ignores duplicates.)

No database schema change is needed.

## The issues in detail

### 1. Tags case sensitivity
- `_addTag` (line 837) dedupes with `_tags.contains(t)` — this is
  **case-sensitive**, so "family" and "Family" can both be added.
- In `_tagsSection` (line 1694) the suggestion filter excludes
  `t.toLowerCase() != query`. So when the user types the exact name of an
  existing tag but in different case (e.g. types "family" while "Family"
  exists), that existing tag is **hidden** from the suggestions, so the user
  can't pick it and ends up creating a near-duplicate.

### 2. Groups list too long
- `_groupsSection` (line 1808) renders one chip per group with no search. Fine
  for a few groups, unusable for many.

### 3. No way to add contacts from Groups page
- `groups_screen.dart` only lets you create / rename-tone / delete a group. It
  has no way to add members. The repository already has `addContactToGroup`.

## The plan for the fix

### Feature 1 — Tags case-insensitive
- In `_addTag`: dedupe case-insensitively. If a tag with the same name
  (ignoring case) already exists in `_tags`, do nothing. If an existing tag
  from `_allTags` matches case-insensitively, reuse that stored casing (so we
  keep one canonical spelling like "Family") instead of the typed casing.
- In `_tagsSection` suggestions: when the query exactly equals an existing tag
  ignoring case but the casing differs, still show it as a selectable
  suggestion (so the user can adopt the existing tag). Keep hiding a suggestion
  only when it is already an added tag. Also keep offering "create new" via the
  existing Add button / enter key.

### Feature 2 — Groups search box (mirrors tags)
- Add state: a `TextEditingController _groupInput` (disposed in `dispose`) with
  a listener that rebuilds as the user types, same as `_tagInput`.
- Rewrite `_groupsSection`:
  - Show selected groups (chips with an "x" to remove) — reuse the current
    on/selected styling but only for `g.on == true`.
  - A search text field "Add to group" + add button.
  - Below it, suggestions: groups from `_groups` whose name contains the query
    (case-insensitive) and are not already selected. Empty query shows the
    first few unselected groups.
  - Tapping a suggestion selects it (`g.on = true`). Pressing enter / add:
    if the typed name matches an existing group (case-insensitive) select it;
    otherwise create a new `_GroupChip(name, true)` — same as the current
    `_addGroup` logic, which already handles case-insensitive reuse.
- Saving is unchanged: `contact.groups` is still built from `_groups` where
  `on == true` (line 1029), so persistence and the group-creation-on-save path
  keep working.

### Feature 3 — Add contacts from Groups page
- Add `GroupRepository.contactIdsInGroup(int groupId)` returning a
  `Set<int>` of member contact ids (simple `SELECT contact_id FROM
  contact_groups WHERE group_id = ?`).
- In `groups_screen.dart`:
  - Add an `'add_contacts'` entry to each group's popup menu (icon
    `person_add_alt`).
  - `_addContactsToGroup(Group group)`: load all contacts via
    `ContactRepository().getAllContacts()` and the current members via
    `contactIdsInGroup`, then show a multi-select bottom sheet (search field +
    checkable list, same search behaviour as `relationship_editor.dart` —
    lowercase substring plus `searchKey` transliteration match).
  - On confirm, call `addContactToGroup` for each newly-checked contact (skip
    ones already members), then `_load()` to refresh counts. Show a snackbar
    with how many were added.
  - The multi-select sheet will be a small private `StatefulWidget` inside
    `groups_screen.dart` (no shared widget needed).
