# Rename namespace + applicationId to `in.sreerajp.contact_sphere`

**Status:** completed

## Issue

The Android app still uses the Flutter template identifier
`com.example.smart_contacts_dialer` for both the Gradle `namespace` and the
`applicationId`. It should be `in.sreerajp.contact_sphere`.

## Scope / occurrences (source tree only)

Grep for `com.example.smart_contacts_dialer` across the repo; the only **source**
hits (everything under `build/` is generated output and is ignored — it
regenerates on the next build):

- [android/app/build.gradle.kts:9](../android/app/build.gradle.kts#L9) — `namespace`.
- [android/app/build.gradle.kts:26](../android/app/build.gradle.kts#L26) — `applicationId`.
- [android/app/src/main/kotlin/com/example/smart_contacts_dialer/MainActivity.kt:1](../android/app/src/main/kotlin/com/example/smart_contacts_dialer/MainActivity.kt#L1)
  — `package` declaration, plus the directory path encodes the old package.

`AndroidManifest.xml` needs **no** change: it references the activity as
`.MainActivity` (relative to `namespace`) and the app as `${applicationName}` —
no hardcoded package.

## Plan for the fix

1. **`android/app/build.gradle.kts`**
   - Line 9: `namespace = "in.sreerajp.contact_sphere"`.
   - Line 26: `applicationId = "in.sreerajp.contact_sphere"`.

2. **Move `MainActivity.kt`** to the directory matching the new package:
   - From `android/app/src/main/kotlin/com/example/smart_contacts_dialer/MainActivity.kt`
   - To   `android/app/src/main/kotlin/in/sreerajp/contact_sphere/MainActivity.kt`

3. **Update the package declaration** in the moved file.
   ⚠️ **`in` is a hard keyword in Kotlin**, so the first path segment must be
   backtick-escaped or the file won't compile:
   ```kotlin
   package `in`.sreerajp.contact_sphere
   ```
   The fully-qualified class name is still `in.sreerajp.contact_sphere.MainActivity`,
   so the manifest's `.MainActivity` continues to resolve. (`.in` is India's ccTLD;
   backtick-escaping reserved segments is the standard Kotlin handling.)

4. **Delete the now-empty old package directories**
   `android/app/src/main/kotlin/com/example/smart_contacts_dialer/` (and the empty
   `com/example`, `com` parents).

## Files to change

- `android/app/build.gradle.kts` — namespace + applicationId.
- `android/app/src/main/kotlin/in/sreerajp/contact_sphere/MainActivity.kt` — **new
  location**, updated `package`.
- `android/app/src/main/kotlin/com/example/...` — **removed**.

## Verification

- `flutter clean` (drop stale `build/` artifacts referencing the old id), then
- `flutter build apk --debug` — the real check that the namespace/applicationId
  and the Kotlin package (with the escaped `in` segment) all compile and the
  manifest merges. `flutter analyze` alone is Dart-only and won't catch this.

## Notes / risks

- Changing `applicationId` makes Android treat this as a **different app**: an
  existing install of the old id won't be upgraded — it installs side-by-side, and
  its local SQLite data does not carry over. Expected for a pre-release rename.
- Release signing is unaffected (still debug keys per the existing TODO).
- The `// TODO: Specify your own unique Application ID` comment at
  build.gradle.kts:25 becomes obsolete; I'll remove it since we're now setting a
  real id.
