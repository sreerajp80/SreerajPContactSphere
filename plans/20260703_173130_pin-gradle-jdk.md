# Pin Gradle JDK to fix "Type T not present" configuration failure

**Status:** completed

## Files to be changed

- `android/gradle.properties` — add `org.gradle.java.home` pointing at Android Studio's bundled JBR (JDK 21).

## The issue

Direct Gradle invocations (`gradlew ...` from `android/`) fail at project-configuration time
with `java.lang.TypeNotPresentException: Type T not present` while AGP creates the
`AndroidUnitTest` component for `:audioplayers_android`.

Root cause: `JAVA_HOME` on this machine is `E:\jdk-24` (Java 24). The project uses
Gradle 8.12, which supports at most Java 23 (Java 24 requires Gradle 8.14+), and
AGP 8.9.1, which is qualified only up to JDK 21. AGP's reflective component-registration
code breaks on JDK 24, crashing every plugin project's configuration before any app code
is compiled. `flutter build` / `flutter run` work because the Flutter tool uses Android
Studio's bundled JBR (Java 21.0.8) instead of `JAVA_HOME`.

## The fix

Add to `android/gradle.properties`:

```
org.gradle.java.home=E:/Android/Android Studio/jbr
```

This makes every Gradle invocation — direct `gradlew` and Flutter-driven alike — use the
same supported JDK 21, independent of the machine's `JAVA_HOME`.

Trade-off noted: this hardcodes a machine-specific path into `gradle.properties`. The
project is not a git repository and is single-machine, so this is acceptable. Alternative
(not chosen): upgrade the Gradle wrapper to 8.14+ and AGP to a Java-24-qualified version —
more churn and re-verification for the same outcome.

## Verification

1. `cd android; .\gradlew :app:tasks` (or the previously failing task) — configuration
   must complete without the `TypeNotPresentException`.
2. `flutter build apk --debug --flavor dev` still builds.
