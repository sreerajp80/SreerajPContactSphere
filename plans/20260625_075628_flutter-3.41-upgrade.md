# Plan — Update project to Flutter 3.41.9 / Dart 3.11.5

**Status:** completed

Date: 2026-06-25 07:56:28 (local)
Precedes the "robust full build-out" plan (`20260625_073730_robust-full-buildout.md`).

## The issue
The installed toolchain is already **Flutter 3.41.9 • Dart 3.11.5** (verified via
`flutter --version`). The *project*, however, still declares/uses an older baseline:

- `pubspec.yaml` `environment.sdk: '^3.8.0'` — works with 3.11.5 but doesn't reflect
  the new target; dependency versions are pinned to older releases and should be
  re-resolved against the current SDK.
- `lib/main.dart:24` passes `CardTheme(...)` to `ThemeData(cardTheme: ...)`. In
  Flutter 3.41 `ThemeData.cardTheme` is typed **`CardThemeData`**; passing
  `CardTheme` is now a **compile error**. (Same migration affects `DialogTheme`,
  `TabBarTheme`, etc. — only `CardTheme` is used here.)
- `lib/screens/contact_list_screen.dart` uses `Color.withOpacity(...)` (lines 113,
  248) which is **deprecated** in 3.41 in favour of `.withValues(alpha: ...)`
  (deprecation warning, not an error).
- Android config is already compatible (AGP 8.7.3, Kotlin 2.1.0, Gradle 8.12,
  compileSdk via `flutter.compileSdkVersion`); Java/jvmTarget is 11. No change
  required for 3.41; Java 17 is optional and **not** included in this plan.

The rest of the project still won't `analyze`/build because of the pre-existing
missing files — those are handled by the separate build-out plan, not here. This
plan's goal is narrow: **make the project's declared toolchain + dependencies target
3.41.9, and fix the one version-driven compile break (`CardTheme`).**

## Files to be changed
1. `pubspec.yaml`
   - `environment.sdk: '^3.8.0'` → `'^3.11.0'` (match Dart 3.11.5; keeps room for
     3.x). Optionally add a `flutter:` version floor — **not** added (kept minimal).
   - Re-resolve dependency versions to the latest compatible with the SDK (see
     command step) and update the version constraints in-file to the resolved
     majors where a major bump is available.
2. `lib/main.dart`
   - `cardTheme: CardTheme( elevation: 2, shape: ... )` →
     `cardTheme: CardThemeData( elevation: 2, shape: ... )`.
3. `pubspec.lock` (generated by `flutter pub get`/`upgrade` — listed for transparency).

## Steps (run after approval)
1. `flutter pub get` — resolve current pubspec against SDK 3.11.5; capture baseline.
2. `flutter pub outdated` — list upgradable packages; decide which majors to take.
3. Edit `pubspec.yaml`: bump `environment.sdk`, then bump dependency constraints to
   the resolved versions (prefer `flutter pub upgrade --major-versions`, then pin the
   constraints it writes). **I will report the exact before/after version set for
   review.**
4. Edit `lib/main.dart`: `CardTheme` → `CardThemeData`.
5. `flutter pub get` again to confirm a clean resolution.
6. `flutter analyze` — expected to still report the *pre-existing* missing-symbol
   errors (those belong to the build-out plan); confirm **no new** errors are
   introduced by the version/dep bump and that `CardTheme` no longer errors.
