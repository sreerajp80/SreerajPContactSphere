# Release build signing (real production keystore)

**Status:** completed

## The issue

The release build is signed with the **debug** keystore
([android/app/build.gradle.kts:41](../android/app/build.gradle.kts#L41)):

```kotlin
release {
    signingConfig = signingConfigs.getByName("debug")
}
```

The debug key is shared and public, so anyone can forge a "signed" update, and Google Play
refuses debug-signed uploads. The user has provided a real production keystore at the repo
root: `keystore.jks`.

Two problems to fix:

1. **Signing** — the release build must use the real `keystore.jks`, not the debug key.
2. **Secret safety** — `keystore.jks` is currently **NOT git-ignored**. The existing
   `android/.gitignore` ignores `key.properties`, `**/*.keystore`, and `**/*.jks`, but only
   *inside* `android/`; the keystore is at the repo root, so it is unprotected. The keystore
   and its passwords must never be committed.

## The fix (standard Flutter signing setup)

Load signing secrets from a git-ignored `android/key.properties` file, build a `release`
signing config from it, and fall back to the debug key when that file is absent (so
`flutter run --release` and CI still work for anyone without the keystore).

**Passwords stay out of the chat and out of git.** I will not ask for or handle the
keystore password, key password, or alias. I add a committed template
(`android/key.properties.example`); the user copies it to `android/key.properties` and fills
in their own values locally.

## Files to change / add

**Change**
- `android/app/build.gradle.kts`
  - At the top, load `android/key.properties` if it exists (via `rootProject.file`, which
    resolves to the `android/` folder).
  - Add a `signingConfigs { create("release") { … } }` block that reads `keyAlias`,
    `keyPassword`, `storeFile`, and `storePassword` from those properties.
  - In `buildTypes.release`, use the `release` signing config when `key.properties` exists,
    otherwise keep the debug fallback. Replace the stale TODO comment.
- `.gitignore` (repo root) — add, for defense-in-depth across the whole repo:
  ```
  # Android release signing — never commit the keystore or its passwords
  *.jks
  *.keystore
  key.properties
  ```
  This covers the root `keystore.jks`. (`android/key.properties` is already ignored by
  `android/.gitignore`; this root rule just makes it belt-and-suspenders.)

**Add (committed)**
- `android/key.properties.example` — a template with empty placeholders and a comment
  showing `storeFile=../../keystore.jks` (path is relative to the `android/app` module, so
  `../../` reaches the repo root where the keystore lives). This file has no secrets and is
  safe to commit; the `key.properties` ignore rule does not match the `.example` name.

**User action (manual, local — not done by me)**
- Copy `android/key.properties.example` to `android/key.properties` and fill in the real
  `storePassword`, `keyPassword`, and `keyAlias`. Adjust `storeFile` if the keystore is
  moved.

## Notes / recommendations

- **Keystore location.** It works at the repo root with the ignore rule above. For extra
  safety many teams keep the keystore *outside* the repo entirely so it physically cannot be
  committed; `storeFile` can point anywhere (an absolute path works). Optional — say the word
  and I'll set an absolute path instead.
- **No Play App Signing decision needed here.** This sets up the upload/app signing key on
  your side. (Earlier discussion: if you later publish to Play, enrol in Play App Signing on
  the first upload so the upload key stays rotatable.)
- **Nothing is committed by me in this change beyond the code/template/ignore edits.** I will
  not `git add` the keystore or any secret.
