# Enable SQLite WAL mode

**Status:** completed

## Issue

The engineering standard §13.2 requires SQLite databases to run in WAL
(Write-Ahead Logging) mode for better concurrent read/write performance.

In [lib/database/database_helper.dart](../lib/database/database_helper.dart),
`_onConfigure` currently enables foreign keys only:

```dart
Future<void> _onConfigure(Database db) async {
  await db.execute('PRAGMA foreign_keys = ON');
}
```

It never sets `journal_mode = WAL`, so the DB stays in the default `delete`
rollback-journal mode. This violates §13.2.

## Files to change

- `lib/database/database_helper.dart` — add the WAL pragma in `_onConfigure`.

## Fix

Add one line to `_onConfigure`, matching the standard's recommended pattern
(WAL set in the same per-connection hook as `foreign_keys`):

```dart
Future<void> _onConfigure(Database db) async {
  await db.execute('PRAGMA foreign_keys = ON');
  await db.execute('PRAGMA journal_mode = WAL');
}
```

Notes:
- `journal_mode = WAL` persists in the DB file header, but `onConfigure` runs
  on every connection sqflite opens, so it is (re)applied safely per connection.
- This applies to both the plain-sqflite open path (tests / non-Android) and the
  SQLCipher open path (on-device); both use `_onConfigure`, so one change covers
  both. SQLCipher supports WAL.
- Also update the `_onConfigure` doc comment to mention WAL.

## Verification

- `flutter analyze` — no new issues.
- Run the app / a DB-backed test and confirm no regression; WAL creates
  `-wal` / `-shm` sidecar files next to the DB, which is expected.
