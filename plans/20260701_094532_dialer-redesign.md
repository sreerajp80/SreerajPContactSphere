# Dialer Screen Redesign + Favorites feature

**Status:** completed

## Source of the change

New design mockups dropped into `sample/`:
- `sample/DialerScreen.dc.html` — the screen design + reference logic.
- `sample/Dialer Canvas.dc.html` — light/dark framing (just shows the screen in a phone frame).

The mock restyles the Dialer with: a top app bar (title + a round "More" button), the
typed-number display moved to the **top** (below the app bar) with an inline backspace,
a scrollable **match/suggestion strip** in the middle (Favorites when empty, live matches
while typing, "Add to contacts" when nothing matches), a T9 keypad with a pressed-key
background, and a call row (call button centered, backspace to its right). The mock also
draws a bottom nav (Contacts/Dialer/Recents) — that already exists in
[home_shell.dart](../lib/screens/home_shell.dart), so it is **out of scope** here (not
duplicated inside the dialer).

## Decisions already made with the user

1. **Favorites empty state → real favorites feature.** The mock shows a "Favorites" list
   before you type. The app has no favorites concept today, so we add one (schema column +
   repository + a way to mark favorites in the contact detail screen).
2. **Number display → raw as typed.** No US-style 3-3-4 grouping (app targets Indian
   users); the on-screen number shows exactly what was typed, just larger/centered. The
   dialed number was already the raw `_number` and is unaffected.

## What is wrong / missing today

- [dialer_screen.dart](../lib/screens/dialer_screen.dart) layout doesn't match the new
  design: number display sits at the bottom, the empty state is a single line of text, the
  suggestion rows have no per-row call action and no phone label, there is no app-bar "More"
  affordance, and there is no "Add to contacts" path for an unknown number.
- No favorites anywhere: no `is_favorite` column, no model field, no repository read/write,
  no UI to mark a contact as a favorite.
- `PhoneMatch` carries no phone **label**, but the design's rows show "Label · number".
- "Add to contacts" wants to open the add form with the typed number pre-filled;
  `AddEditContactScreen` currently has no way to seed an initial number.

## Files to change

### Data layer (favorites)
1. **`lib/database/database_helper.dart`**
   - Bump DB `version` 7 → 8.
   - Add `is_favorite INTEGER DEFAULT 0` to the `contacts` `CREATE TABLE`.
   - Add a `v7 → v8` upgrade branch: `ALTER TABLE contacts ADD COLUMN is_favorite INTEGER DEFAULT 0`.
   - Add an index `idx_contacts_is_favorite` (in `_createIndexes`, created + in the v8 branch).

2. **`lib/models/contact.dart`**
   - Add `bool isFavorite` field (default `false`), wire into constructor, `toMap`
     (`'is_favorite': isFavorite ? 1 : 0`), and `fromMap` (`map['is_favorite'] == 1`).

3. **`lib/repositories/contact_repository.dart`**
   - Extend `PhoneMatch` with a `final String? label;` (nullable) and populate it from
     `p.label` in `findByPhoneFragment` (add `p.label AS label` to the SELECT).
   - `Future<void> setFavorite(int contactId, bool value)` — `UPDATE contacts SET
     is_favorite = ? WHERE id = ?`.
   - `Future<List<PhoneMatch>> getFavoriteMatches({int limit = 20})` — favorites
     (`is_favorite = 1`, non-secret) with their primary phone number + label via a
     correlated subquery, name assembled the same way as `findByPhoneFragment`, ordered by
     `first_name`. Favorites with no phone are still returned (empty number → call action
     disabled on that row).
   - Include `is_favorite` in the `_summarySelect` projection **only if** needed by the
     contact card (not required for this change — left as a note, no card change planned).

### Add/Edit (prefill for "Add to contacts")
4. **`lib/screens/add_edit_contact_screen.dart`**
   - Add an optional `final String? initialNumber;` to the constructor.
   - In `initState`, when `widget.contact == null` and `initialNumber` is non-empty, seed a
     single phone entry (label `Mobile`, `isPrimary: true`) so the add form opens with the
     number filled and the title still reads "Add contact".

### Contact detail (mark a favorite)
5. **`lib/screens/contact_detail_screen.dart`**
   - Add a star `IconButton` to the `AppBar.actions` (before edit/delete): filled
     `Icons.star` when `contact.isFavorite`, `Icons.star_border` otherwise. Tapping toggles
     via `ContactRepository.setFavorite`, updates the in-memory contact, and `setState`s.

### Dialer screen (the redesign)
6. **`lib/screens/dialer_screen.dart`** — rebuild `build()` and helpers to the new layout,
   reusing existing state (`_number`, `_suggestions`, `_linkedContactId/_linkedName`,
   `_refreshSuggestions`, `startCall` from `CallLifecycleMixin`):
   - **App bar row:** "Dialer" title (w800) + a round "More" button (`PopupMenuButton`)
     offering **Settings** (routes to `SettingsScreen`, already reached the same way from the
     contact list). This is the only menu item for now.
   - **Number display (top):** centered, large (~34px, w700), raw `_number`; caption
     "Start typing to find a contact" when empty; inline backspace button when non-empty.
   - **Match/suggestion strip (Expanded, scrollable):**
     - Empty input → load favorites (new `getFavoriteMatches`) under a "FAVORITES" header
       (circle avatar with initial). If there are no favorites, show a small muted hint.
     - Typing with matches → "N match/matches" header + rows (rounded-square avatar), each
       showing name and "Label · number".
     - Typing with no match → an "Add to contacts" card (opens `AddEditContactScreen`
       with `initialNumber: _number`) + a muted "No saved contact for this number yet." line.
     - **Row interactions (documented so no current behavior is lost):** tap row → select
       (fills `_number` + links the contact, current behavior); the accent **call button**
       on the row → place the call directly (`startCall`); long-press row → open
       `ContactDetailScreen` (replaces today's trailing "open contact" button).
   - **Keypad:** unchanged keys/letters; keep long-press `0` → `+`; pressed key shows a
     rounded background (accent-soft).
   - **Call row:** accent gradient call button centered (long-press → clear, as today) +
     a backspace button to its right (per the mock). Backspace stays next to the number
     display too.
   - Favorites are (re)loaded when the input becomes empty (in `_clear`/`_backspace`/initial
     load) via a new `_loadFavorites()` guarded by the existing `_queryToken` so stale async
     results are ignored.

## Explicitly out of scope
- The bottom navigation bar (already in `HomeShell`).
- Any change to the Contacts list card (favorites star there) — can be a follow-up.
- Number formatting/grouping (user chose raw).

## Testing
- `flutter analyze` clean on all touched files.
- `flutter test` — existing `test/widget_test.dart` still passes (it only checks the shell
  and nav; the dialer changes don't touch those assertions).
- Manual: DB upgrades from v7 without loss; mark/unmark a favorite in detail → it appears in
  the dialer's empty-state Favorites; typing surfaces matches with label · number and a
  working per-row call; unknown number shows "Add to contacts" and opens the add form
  pre-filled; keypad, backspace, and call button behave.

## Notes / risks
- DB migration is additive (single `ALTER TABLE` + index) — low risk, existing rows default
  to not-favorite.
- Passing `initialNumber` (rather than a pre-built `Contact`) keeps the add form's
  "Add contact" title and insert-vs-update logic correct.
